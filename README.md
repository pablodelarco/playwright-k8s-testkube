# Playwright on Kubernetes with Testkube

Companion repo for the ScrapingBee post *Orchestrating High-Concurrency Playwright Clusters on Kubernetes with Testkube*.

A 144-test Playwright suite (48 spec files) split into N shards, each shard running as its own pod through a Testkube Test Workflow, with the blob reports merged into one HTML report at the end.

## What is in here

| Path | What it does |
|---|---|
| `app/server.js` | Tiny HTTP app under test. Renders a product list with client-side JS after 150 ms, so every test waits on real rendering. |
| `tests/` | 48 spec files, 3 tests each. Generated by `scripts/generate-tests.js`. |
| `playwright.config.ts` | Blob reporter when `CI=1`, `WORKERS` env for contexts per pod, `--disable-dev-shm-usage` for Chromium in containers. |
| `k8s/testworkflow.yaml` | The Testkube Test Workflow: install, parallel sharded step, merge. |
| `scripts/benchmark.sh` | Runs the workflow at 1, 8 and 32 shards and prints a wall-clock table. |

## Run it locally

```bash
npm ci
npx playwright install chromium
npx playwright test                 # whole suite, 2 workers
CI=1 npx playwright test --shard 1/4   # one shard, writes blob-report/report-1.zip
```

Merge shards run on one machine:

```bash
mkdir -p reports
for i in 1 2 3 4; do
  rm -rf blob-report
  CI=1 npx playwright test --shard $i/4
  cp blob-report/report-$i.zip reports/
done
npx playwright merge-reports --reporter=html reports
npx playwright show-report
```

## Run it on Kubernetes

Requirements: a cluster you can `kubectl` into, Helm 3, the Testkube CLI.

```bash
helm repo add kubeshop https://kubeshop.github.io/helm-charts
helm repo update
helm upgrade --install testkube kubeshop/testkube \
  --create-namespace --namespace testkube --set installCRDs=true

kubectl apply -f k8s/testworkflow.yaml
testkube run testworkflow playwright-sharded --config shards=8 --watch
```

Before the first run, edit two things in `k8s/testworkflow.yaml`:

1. `content.git.uri` if you forked the repo.
2. `parallelism` on the parallel step. Set it to how many 2 GiB pods your nodes can hold at once. Shards beyond that number queue instead of piling up in `Pending`.

Fetch the merged report:

```bash
testkube get testworkflowexecution   # find the execution id
testkube download artifacts <execution-id>
```

## Benchmark

```bash
RUNS=2 scripts/benchmark.sh 1 8 32
```

Prints shards, run number, wall-clock seconds, pods created, `FailedScheduling` events and `OOMKilled` containers per run. Per-run CLI output lands in `/tmp/bench-<shards>-<run>.log`.

## Versions used

- Playwright 1.63.0, image `mcr.microsoft.com/playwright:v1.63.0-noble`
- Node 24 (v24.20.0 inside the `v1.63.0-noble` image)
- Testkube Test Workflows API `testworkflows.testkube.io/v1`
